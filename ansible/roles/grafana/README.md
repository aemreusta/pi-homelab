# grafana

Grafana provides dashboards and the Explore UI over VictoriaMetrics (metrics)
and VictoriaLogs (logs), with Authelia OIDC login.

## What it deploys

A single `grafana/grafana-oss:latest` container (`grafana`), running as UID
`472` with `cap_drop: [ALL]`, a read-only root filesystem and a tmpfs `/tmp`.
It is on the `observability` bridge network, which this role creates, and
reaches `victoriametrics:8428` and `victorialogs:9428` by container name.

| Item            | Value                                                  |
|-----------------|--------------------------------------------------------|
| Web UI          | host `:3003` → container `:3000` (UFW: `192.168.0.0/16`) |
| Traefik (HTTPS) | `https://grafana.example.internal`                     |
| Data            | `/home/pi/docker/observability/grafana/data`         |
| Dashboards      | `/home/pi/docker/observability/grafana/dashboards`   |
| Memory limit    | `grafana_mem_limit` (768M)                             |

Datasources (`VictoriaMetrics` is the default, plus `VictoriaLogs`) are
provisioned read-only. Dashboards come from two sources: the grafana.com IDs
in `grafana_dashboards`, fetched best-effort, and the homelab JSONs in
`files/dashboards/`.

## Deploy

```bash
make grafana       # or `make observability` for the whole stack
```

OIDC login depends on the `authelia` role (client `grafana`) and the internal
CA generated by the `traefik` role, mounted from `grafana_internal_ca_src`.

## Configuration

- `grafana_admin_user` / `vault_grafana_admin_password`: local admin. If the vault var is missing the password falls back to `admin`. This account is the break-glass login when Authelia is down.
- `vault_authelia_grafana_client_secret`: plaintext OIDC client secret. Authelia holds the hash. Authelia group `admins` maps to Grafana Admin; everyone else is Viewer.
- `grafana_plugins`: `victoriametrics-logs-datasource`, installed with `GF_PLUGINS_PREINSTALL_SYNC` and allowed as unsigned.
- `grafana_log_level` (`warn`): silences the every-30s dashboard-service info spam.
- `grafana_tmpfs_size` (256m): the plugin archive is downloaded to `/tmp`. At 64m the install failed and the container entered a restart loop.

## Operations

- Healthcheck: `wget --spider http://localhost:3000/api/health` (60s start period).
- `grafana_mem_limit` was raised from 384M after OOM-style restart loops at
  boot. The comment cites Grafana's 750 MiB documented minimum.
- The OIDC back-channel verifies Traefik's self-signed leaf against the
  mounted CA (`GF_AUTH_GENERIC_OAUTH_TLS_CLIENT_CA`). Never switch it to
  skip-verify. See [internal CA HTTPS](../../../docs/design/033-internal-ca-https.md).
- Dashboards fail to download when grafana.com is unreachable. The play only
  warns, so re-run `make grafana` later.
