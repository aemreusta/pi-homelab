# 2026-07-16 — Watchtower pulled a distroless victoria-logs image; the exec healthcheck went permanently unhealthy

- **What happened:** Watchtower's 08:44 session updated `victoriametrics/victoria-logs:latest` to v1.52.0 (published upstream the same day). The new image is distroless — no shell, no wget, no busybox — so the compose healthcheck (`wget --spider :9428/health`) failed with `exec: "wget": executable file not found in $PATH` on every probe. The container sat `(unhealthy)` for ~8 h with a **976-strike failing streak** while the service itself was fine the entire time (`/health` → 200, fluent-bit shipping ~2 k rows/5 min, Grafana queries working). Three manual `docker restart`s (12:45/13:00/13:15) couldn't help — nothing in-container can run.
- **Why:** The healthcheck depended on a userland tool inside a vendor `latest` image, and watchtower deploys upstream base-image changes on *its* schedule, not ours. Upstream dropping the shell is a legitimate hardening move; our probe was the fragile part.
- **Class:** **exec-healthcheck depends on in-image userland of a `latest` image** — adjacent to the known "scratch = no healthcheck possible" set (portainer, beszel), but new in that a *previously working* healthcheck was broken by an upstream rebase, not by our own image choice. First instance of the break-by-rebase shape.
- **Occurrence:** 1st. Known-vulnerable siblings: victoriametrics, vmagent, vmalert (×2 containers) run the same `wget --spider` pattern against `latest` images from the same vendor — tracked as an immediate follow-up.
- **Structural fix:** `deploy-v2026.07.16.1` (`ee3d639`) — healthcheck removed from the victorialogs compose template with a pointer comment, and liveness moved to the scrape path: new `VictoriaLogsDown` vmalert rule (`up{job="victorialogs"} == 0`, crit, 5 m) in `observability-services.yml`. This also closed a pre-existing blind spot: every LogsQL-based alert (container-error-rate group) silently depends on VL being up, and nothing alerted on VL itself. **Tell for next time:** a container that flips `(unhealthy)` right after a watchtower session while its endpoints answer fine → inspect `.State.Health.Log` for `executable file not found` before restarting anything; the fix is never a restart.
