# 2026-09-28 — Mac sleep left the GitHub runner down 19h; Mac alerts flapped as a burst

- **What happened:** The Mac worker (a MacBook on battery + Wi-Fi) drifted in and out of sleep, then hit Low Power Sleep at 1% battery (01:10 → 07:47 hibernation). On resume the runner supervisor's Docker NFS volume mount timed out once; its login-only LaunchAgent exited 0 and nothing retried, so CI was offline ~19h (`GHRunnerSupervisorDown`). Meanwhile each sleep produced a separate page per Mac-dependent signal (NFS read ×2, worker heartbeat ×2, runner, offload skip) plus their resolves — ~15 pushes for one root cause.
- **Why:** (1) The runner LaunchAgent was a one-shot `docker compose up -d` — the exact shape a sibling Mac compose LaunchAgent had already been fixed for, but the fix lived in that one plist. (2) The Pi had no Mac-presence signal, so "Mac asleep" and "Mac broken" were indistinguishable and every dependent alert paged independently. The Pi side was healthy throughout (load 2, idle network, no nfsd errors).
- **Class:** Recovery fix applied per-instance instead of per-class (same shape re-shipped in a sibling file); root-cause alert missing so symptoms page individually.
- **Occurrence:** 2nd for the one-shot LaunchAgent (1st: a sibling Mac compose job's 26-day outage). 1st for Mac-presence-less alerting.
- **Structural fix:** Shared, Bats-tested ensure-compose helper for every Mac compose LaunchAgent (15-min StartInterval, real exit codes) + `tests/test_mac_launchagents.py` guarding the class. Pi-side `homelab-agent mac-presence` probe → `MacWorkerAway` inhibits every `mac_dependent="true"` alert (incl. a 15-min settle window after wake). Operational: keep the MacBook on AC power — no software makes a 1%-battery laptop a worker.
