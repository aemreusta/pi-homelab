# 2026-06-06 — ntfy delivered nothing for 36h while every health check stayed green

- **What happened:** Operator reported no ntfy notifications for ~36h. The entire publish path was healthy — Alertmanager sent (`alertmanager_notifications_total{webhook}=2, failed=0`), bridge→ntfy returned `{"healthy":true}`, `ntfy_messages_published_success=62` — but `ntfy_subscribers_total=0` and there is **no FCM/UnifiedPush proxy** configured, so delivery is persistent-connection-only. With zero subscribers, all 62 published messages reached no device. `NtfyDown` (`up{job="ntfy"}==0`) never fired because the container was up and scrapeable the whole time.
- **Why:** Monitoring covers the **publish** side (is ntfy up, are messages accepted) but not the **delivery** side (is anyone subscribed to receive them). `subscribers=0` on a self-hosted, push-proxy-less ntfy means the client isn't holding its streaming connection — undetectable from `up==0`. (Red herring along the way: the bridge's `/var/log/alert-audit.log` ENOSPC errors on 06-04 were a *disk-full* tail, not the cause; the bridge logs to stdout only on failure, so its quiet stdout post-06-04 meant audits were succeeding to file, not that it was dead.)
- **Class:** Delivery-side blind spot — a health check that proves the pipe accepts input but not that output reaches anyone. Sibling of silent-cron (counter exists but no alert watches it): here the publish metric is green but no rule watches the delivery metric.
- **Occurrence:** 1st recorded for ntfy delivery. Tangentially the Nth tail of the 2026-06-04 disk-full cascade (which also wedged speedtest — see that day's metric-freeze).
- **Structural fix:** **Deferred — operator chose client re-subscribe over a code change (2026-06-06).** The durable fix is a vmalert rule on `ntfy_subscribers_total == 0` (sustained, warn) and/or a push proxy (`upstream-base-url`) so delivery survives a dropped persistent connection — the latter is mandatory for reliable iOS/background delivery. `NtfyDown` cannot cover this class; it only sees `up==0`. Tracked here until a recurrence justifies shipping the rule.
