# 2026-07-11 — tailscale-dns dark ~3h with an empty Docker network endpoint (REFUSED on every forward)

- **What happened:** `tailscale-dns` was `unhealthy` for ~3h. dnsmasq (PID 7) was up and listening on `0.0.0.0:53`; local `address=/homelab/` rewrites still resolved, but *every query needing upstream forwarding* — the healthcheck's `google.com`, all AAAA — returned `REFUSED`. Remote Tailscale clients got no answers. AdGuard (primary LAN DNS) masked it, so nothing user-facing broke.
- **Why:** `docker inspect` showed `NetworkSettings.Networks == {}` — the container was attached to **no network at all** (empty route table, `ping 1.1.1.1 → Network unreachable`). With no egress dnsmasq can't reach `1.1.1.1`/`9.9.9.9`, and dnsmasq answers un-forwardable queries with `REFUSED` (not SERVFAIL), which reads like a config fault but wasn't — the config was fine. The container had restarted ~3h earlier and came back with its `tailscale-dns_default` endpoint lost; tini then spammed `FATAL … forwarding signal: 'Operation not permitted'`, a symptom of the same wedged network namespace state.
- **Class:** Container survives (process up, port bound, healthcheck present) but loses its Docker network endpoint → egress-dependent function silently fails while liveness looks green. Sibling of the "health check proves input accepted, not output received" delivery-blind-spot class — here the healthcheck *did* flip unhealthy, but there was no alert/auto-remediation, so it sat dark for hours.
- **Occurrence:** 1st of this exact shape (empty `NetworkSettings.Networks`). Recovery mirrors past network-wedge recoveries but the cause is new.
- **Structural fix:** Recovery = `docker compose down && up` in the compose dir (recreates the network + reattaches; `restart`/redeploy would NOT have reattached a lost endpoint — compose sees an unchanged config hash and leaves it). Deferred: a vmalert rule on sustained `unhealthy` container health (the healthcheck caught it but nothing watched the healthcheck), and an outbound-forwarding probe (local rewrite success hid the egress failure). Diagnostic tell for next time: `docker inspect <c> --format '{{json .NetworkSettings.Networks}}'` == `{}` + `REFUSED` on forward but OK on local `address=`.
