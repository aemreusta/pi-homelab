# 2026-07-16 — ntfy-bridge crashed on em-dash alert titles: notifications silently undelivered, audit log blind

- **What happened:** During the evening's alert transitions (21:31–21:35, the VL-fix deploy window) ntfy-bridge's stderr filled with `UnicodeEncodeError: 'latin-1' codec can't encode character '—'` tracebacks. Python's `http.client` encodes HTTP headers as latin-1; the bridge put the alert `summary` verbatim into the ntfy `Title` header, so **every alert whose summary contains an em-dash — which most rule summaries in this repo do — crashed the handler thread mid-send**: no notification delivered, and (worse) the crash happened *before* the `audit()` call, so `alert-audit.log` showed nothing. Alertmanager's retries just re-crashed it. Separately, 2×/day `ntfy POST failed: Name does not resolve` — transient Docker embedded-DNS blips on `ntfy.example.internal`.
- **Why:** The delivery-proof audit line is written *after* the send, so an exception inside the send path defeats the audit trail that exists precisely to prove delivery. Nothing exercised a non-ASCII title: the bridge tests used ASCII-only fixtures, and the vmalert quoting convention/tests check YAML quoting, not character repertoire.
- **Class:** **silent notification delivery** — 2nd instance (1st: 2026-06-06 `subscribers=0`, 36 h all-green). Same shape: every health signal green while the delivery path is dead; only the delivery-side artifact (stderr traceback here, subscriber gauge there) shows it.
- **Occurrence:** 2nd of the class → structural fix now, per the incident-log doctrine.
- **Structural fix:** `deploy-v2026.07.16.2` (`a176c10`) — (1) `header_safe()` RFC 2047-encodes (`=?UTF-8?B?…?=`) any non-latin-1 header value; ntfy documents this exact escape hatch for libraries without UTF-8 header support. (2) `send_ntfy` catches broad exceptions and **never raises** — the audit line is now written on every path, so a future send-path failure shows up as `status=fail` instead of nothing. (3) One 2 s retry on transport errors rides out the DNS blips. Guarded by 4 tests incl. an em-dash end-to-end regression. **Tell for next time:** when a component exists to *prove* something happened (audit/metric emit), any code that can throw between the action and the proof is a blind-spot bug — write the proof in a `finally`-equivalent path.
