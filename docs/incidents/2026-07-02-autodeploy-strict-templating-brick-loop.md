# 2026-07-02 — homelab-autodeploy multi-day brick loop (strict ansible-core 2.21 + self-reverting rollback)

- **What happened:** The first push that carried a real ansible change (`44d6a1e`) tripped the Pi-side GitOps CD (`homelab_autodeploy`) into a days-long fail→rollback→ntfy-storm loop. Each 5-min cron run re-deployed the whole heavy stack and died at a *different* spot every time — `ansible-playbook: command not found`, then a media-app role's `object of type 'dict' has no attribute 'json'`, then `ufw: ERROR problem running sysctl`, then the same `.json` crash marching through `when` → `method`/`url` task-args — rolling back on each and re-storming ntfy (high/max priority).
- **Why:** Four entangled causes. (1) root cron's bare PATH (`/usr/bin:/bin`) couldn't see the uv-installed `/usr/local/bin/ansible-playbook`. (2) The plan/rollback baseline was `git rev-parse HEAD`, but a failed run rolls the checkout back to the last-good commit, pinning HEAD there → every later plan diffed the **whole** stack from that stale point, replaying 5-6 heavy roles under disk-pressure and tripping a fresh transient each run. (3) Rollback re-deployed `homelab_autodeploy` from the pre-fix commit, **reverting the very fix just shipped** (PATH export, retry loop). (4) — **corrected 2026-07-02 after live verification** — the Pi runs ansible-core 2.21 (strict) while the Mac runs 2.20.5 (lenient), so deploying that role from the Mac passed while the Pi's `--connection=local` run crashed. But 2.21 is the **detector, not the source**: the real bug is that role's config tasks' `register: X` → `X.json` chain that assumes every `uri` result carries `.json`. A **behavioral probe on the Pi** proved `until: "'json' in X"` is *not* dead code (a jsonless-200 retries 4× then fails loudly); the actual crash is when a GET is **skipped** (registers `{skipped:true}`, no `.json`) or a downstream task consumes `X.json` in its **args** (`method:`/`url:`/`body:`) with no `when:` guard — exactly the role's qBittorrent download-client upsert task. The 2026-07-02 per-consumer guards were whack-a-mole because guarding a GET with `when:` skip-poisons its result for the next consumer.
- **Class:** (a) **self-sabotaging rollback** — CD that deploys itself and rolls back to a commit predating its own fix; (b) **plan baseline from mutable checkout HEAD, not authoritative state**; (c) **check-mode `uri`-skip poisons `.json` consumers** — **RESOLVED 2026-07-02 (superseded the "strict-templating / 2.21-vs-2.20.5" framing, which was a red herring)**: `ansible.builtin.uri` is *skipped* in `--check` mode (registers `{skipped:true}`, no `.json`), and the autodeploy deep-check runs `--check --diff` before apply, so every config GET skipped → the `Upsert method:` crashed at arg finalization. Reproduces on 2.20.5 too → **pinning fixes nothing**. Fix = `not ansible_check_mode` on live-API config includes; class guard `tests/test_uri_check_mode_safety.py` found the same latent trap in three more roles, incl. **beszel** and **jellyseerr**. Named row added to the recurring-classes table.
- **Occurrence:** 1st of this shape. (Distinct from the valid-YAML/invalid-to-consumer monitoring-config class — this is host templating strictness, not a quoting collision.)
- **Structural fix:** **Shipped:** `/usr/bin/ansible-playbook` symlink (create-only → survives rollback, on cron's bare PATH); plan/rollback baseline now reads `state.last_good_sha`; `deploy_target` retries 3× with backoff before rollback; the media role's API GET `until`s → `'json' in X`; a "wait until the app's config API serves JSON" readiness gate; `'json' in X` guards on all `.json`-consuming `when`s. **Rejected (2026-07-02, corrected):** pinning the Pi to ansible-core 2.20.x is **warning suppression** — it re-hides the latent `.json` bug and risks silent misconfiguration (the `Upsert` would POST a duplicate client instead of PUT). Violates the repo's "do not pass on warnings" rule and the "latest everything" directive. **Deferred to a follow-up RCA, TDD fix map:** Phase 1 — a static invariant test (modeled on `test_vmalert_rules.py`) that fails CI on any unguarded `.json` consumer or skip-capable feeding GET, then fix all instances at once (no whack-a-mole); Phase 2 — narrow autodeploy blast radius; Phase 3 — widen the readiness gate + fix the sibling bugs (e.g. `node_exporter_cd_rollback_test_undefined`); Phase 4 — add the class to the recurring-classes table. **RESOLVED 2026-07-03:** root cause was **check mode**, not strict templating / an ansible-core version delta (`--check` *skips* every `uri`, poisoning `.json` consumers — reproduces on 2.20.5 too, so **pinning fixes nothing**; the "2.21-strict" framing was a red herring that cost days). The class fix (`when: … and not ansible_check_mode` on live-API config phases) was swept across the affected roles (incl. `beszel`/`jellyseerr`) and, with the correct rollback restore-set (R4) + `homelab_autodeploy_held` gauge/alert + a repo-wide guard test + the end-to-end **CD drill** (`make cd-drill`), auto-deployed green in sequence (`2214ad7`→`335e37e`→`7299af4`). Live state: `last_good=7299af4`, `failed_sha` cleared, `homelab_autodeploy_held 0`. Meta-lesson in [ops-discipline §6](../operations/ops-discipline.md).
