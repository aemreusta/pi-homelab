# 2026-07-14 — CD rollback: adguard `configure.yml` check-mode `uri`-skip (`.content` variant) blocked the SSO Phase 0 tag

- **What happened:** The SSO Phase 0 tag (`deploy-v2026.07.14.3`, UFW LAN-scoping across 11 roles) was picked up by the CD. `adguard` was a changed role, so the CD deep-check (`--check --diff`) ran its `configure.yml` — which crashed with `object of type 'dict' has no attribute 'content'`, failed 3/3 (rc=2), and triggered a rollback. The rollback redeploys the attempted targets, so it re-ran adguard at last-good and hit the *same* crash → `ROLLBACK FAILED at adguard`. Net effect on the box: **nothing** — the failure was entirely in `--check` (no live mutation); AdGuard stayed `Up (healthy)`, DNS kept resolving, and no Phase 0 change was applied (the deploy aborted at the first target). Commit `6ba9c1e` was left held.
- **Why:** `configure.yml`'s `Get current DNS rewrites` is an `ansible.builtin.uri` GET — **skipped under `--check`** — so its register `adguard_current_rewrites` is a bare `{skipped: true}` dict. The next task loops `adguard_current_rewrites.content | from_json` and the `Add` task's `when:` reads the same `.content`, both crashing at arg-finalization. This is the check-mode `uri`-skip class, identical to the [2026-07-02 autodeploy brick](2026-07-02-autodeploy-strict-templating-brick-loop.md) and the [2026-07-14 zot htpasswd rollback](2026-07-14-cd-self-sabotaging-rollback-zot-check-mode.md) — but the **`.content` (raw body via `return_content: true`) variant**, where the prior instances were `.json`. The repo guard `tests/test_uri_check_mode_safety.py` only matched `.json` access, so it never flagged this latent case. adguard hadn't been redeployed since the pattern was written, so the deep-check gate had never exercised it until a UFW change made adguard a deploy target.
- **Class:** check-mode `uri`-skip → a `--check`-skipped register consumed by a later task's `loop`/`when`/args. Cross-cutting with the "a benign change (UFW scoping) surfaces a latent bug in an unrelated part of the same role" shape — the CD deploys the *whole* role, not just the changed file.
- **Occurrence:** 3rd of the check-mode `uri`-skip class (`.json` 2026-07-02; zot htpasswd-copy 2026-07-14; adguard `.content` 2026-07-14). 1st `.content` variant, and 1st that the guard test structurally missed.
- **Structural fix:** (1) Gate the `configure.yml` include with `when: not ansible_check_mode` in `adguard/tasks/main.yml` — the canonical fix (the deep-check no longer previews DNS-rewrite changes; they apply live). (2) **Close the guard gap:** extend `tests/test_uri_check_mode_safety.py` to match `.content` as well as `.json` (and the inline `'content' in X` short-circuit). The extended test flagged adguard RED before the gate and GREEN after — so the class now includes the raw-body variant. Re-shipped under the next deploy tag after pre-flighting `--check` on all 11 changed roles. Tell for next time: when a plain change (firewall, labels) makes an otherwise-untouched role a CD target, its *entire* role runs through the deep-check — pre-flight `ansible-playbook <role>.yml --check` on every changed role before tagging, not just the file you edited.
