# 2026-07-14 — CD silently skipped speedtest_tracker (role→playbook name mismatch, false success)

- **What happened:** After `deploy-v2026.07.14.4` deployed `ok`, 16 of the 17 Phase 0 UFW ports were LAN-scoped — but `speedtest :8765` was still `Anywhere`, despite the role having the correct scoping committed and the deploy reporting success. The CD never applied speedtest's `ufw.yml`. (Also surfaced during the audit: an orphan `Glances :61208 ALLOW Anywhere` rule with no role and no running container — a stale rule from a long-gone service.)
- **Why:** The CD maps a changed role dir → a `make`/playbook target. `homelab_autodeploy_role_target_map` was empty (`{}`), so `_role_to_target` fell back to the underscore→hyphen convention: `speedtest_tracker` → `speedtest-tracker`. But the playbook is `playbooks/speedtest.yml` (the role drops the `_tracker` suffix), so `playbooks/speedtest-tracker.yml` does not exist. `deploy_target()` then hit `[ -f "$pb" ] || { log "no playbook … — skipping target"; return 0; }` — it **returns 0 (success)** for a missing playbook, so the mis-mapped role was dropped from the plan as a *false success*: no error, no rollback, no ntfy. The convention works for every other role (e.g. `uptime_kuma`→`uptime-kuma.yml`); speedtest_tracker was the lone exception and had no override.
- **Class:** silent-skip / silent-success (the silent-cron family the repo's agent rules forbid) — a planned unit dropped without a signal, indistinguishable from "nothing to do." Adjacent to the observability rule "silent-zero == silent-failure."
- **Occurrence:** 1st of the role→playbook name-mismatch shape. The unit tests used a *fabricated* `ROLE_MAP` fixture that happened to avoid the gap, so the real (empty) production map was never exercised.
- **Structural fix:** (1) Add `speedtest_tracker: speedtest` to the production `homelab_autodeploy_role_target_map`. (2) New guard `tests/test_homelab_autodeploy.py::TestRoleTargetMappingIntegrity` — parses the **real** production map + `base_roles` from defaults and asserts every role with a `tasks/deploy.yml` resolves (via the actual `_role_to_target`) to an existing `playbooks/<target>.yml`; RED on speedtest_tracker before the map entry, GREEN after. (3) Applied speedtest's scoping via `make speedtest` and deleted the orphan Glances rule live. **Follow-up (tracked, not done — touches the never_auto controller):** make `deploy_target()` *loud* (ntfy) when a planned target has no playbook, instead of a silent `return 0`, so a future mapping miss is surfaced even if the guard is somehow bypassed. Controller changes ship via a manual `make homelab-autodeploy` bootstrap. Tell: after a full-rollout deploy, audit that each changed role's *effect* actually landed (the port flipped), not just that the CD said `ok`.
