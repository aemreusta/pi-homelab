# 2026-10-11 — indexer observer claimed a shared metric directory

- **What happened:** the new media observer declared `/var/lib/node_exporter/textfile` root-owned. A late read of the deep-check diff showed existing ownership was `pi:pi` mode 0755; root ownership would block user collectors' atomic writes. Corrected the Pi checkout's single ownership block during rollout, preserved/restored the live owner, and reconciled it in `deploy-v2026.10.11.3`. The user was informed.
- **Why:** the root-run observer legitimately owns its private state and emitted file, but applied that ownership to the shared parent. The existing guard skipped its `{{ media_indexer_health_textfile | dirname }}` path, so passing tests missed the conflict. The changed-owner diff was not examined sufficiently before tagging.
- **Class:** multi-role shared-directory ownership conflict hidden behind an unresolved path alias; late deep-check review.
- **Occurrence:** recurrence of the 2026-08-04 control-directory ownership failure and the [ownership discipline](../operations/ops-discipline.md). This window's control-directory conflict was caught earlier, but its correction did not cover the shared textfile directory.
- **Structural fix:** use `docker_user` for the shared directory; root retains private state/file ownership. Extend the existing guard for bounded `dirname` resolution and explicit textfile owner coverage. The original tag fails the new regression guard; corrected source passes. Verify an actual `pi` atomic temporary write and recheck both canonical tagged deployment and natural collector freshness.
